# Gateway domain contract

- `service-key-rotation.ts` is the release-only canonical-subject key rotation boundary. It accepts a strict target DTO, verifies the currently deployed one-time secret against the active hash, locks and replaces the row through Drizzle in one transaction, and records a secret-free Admin audit event. An explicit `force=true` rotates a compromised key even when scopes are unchanged. Runtime routes never call this service, and dry-run/apply receipts expose only scope drift and proof status.

- 本目录实现 Gateway 鉴权、模型解析、429 限流、订阅 402 资格、请求生命周期与结算；所有部署执行同一生产合同。
- 同一平台用户的预授权、在线结算与未知用量核对必须先取得 `ink-memory:gateway-account` 命名空间加 `platformUserId` 的 PostgreSQL 两键事务级 advisory lock，再按请求、日/分钟/月限流、Allowance 与现金账户顺序取行锁；模型调用位于事务外。该锁跨进程生效并随提交/回滚释放，不使用进程内互斥或紧密 CAS 自旋。
- 用户默认 429 阈值来自 `config/gateway-default-limits.mjs`，只限制实时用量，不发放订阅 Token、不增加 Allowance 或现金余额。
- Provider Secret、Gateway Key 与 DSN 不得回显；测试通过依赖注入、受控 mock Provider 和明确隔离 PostgreSQL 完成。
- `provider-transport.ts` 对 generic、Codex、xAI、Copilot 推理失败统一读取上游正文：有效 JSON 保留结构，其他正文保留文本，先移除凭据字段及当前/续期前认证 Header 的回显值，再由既有 `gateway_response_payloads.error_body` 捕获。公开 Gateway 错误继续只返回稳定分类；原始错误证据只通过 `gateway.payloads.read`、查看确认与审计的 Admin 完整报文入口读取。非流式 401 仍只续期/重放一次并保存最终失败正文，流式请求不重放。
- Provider 静态凭据 header 由 `provider-auth.ts` 按协议 capability 统一解析，Admin 最小验证、SDK client 与 raw transport 必须复用该解析器；OpenAI-compatible 只接受 Bearer，Anthropic 默认 `x-api-key` 并仅在明确配置时使用 static Bearer。Bearer 不等同于 OAuth。
- 托管 Header 合并复用 `models/request-headers.ts`：只有 Codex 模型显式配置的 `user-agent` 和 `version` 可覆盖默认客户端标识，首次请求与 401 续期重放保持一致。Authorization、账号身份、originator 与其他托管产品元数据仍由 Provider 管理；客户端标识调整不触发重新 Device 认证。
- 静态 Provider endpoint 始终执行 SSRF/host policy；localhost 仅由显式 `AI_PROVIDER_ALLOW_INSECURE_LOCALHOST=true` topology capability 开启，不再读取 development/test/production 名称改变行为。
- Gateway 只读取 PostgreSQL 当前 effective 加密凭据；candidate 或失败轮换不得进入执行面。存量 active/unverified Provider 保持既有 readiness，不能把 validation metadata 变成新的运行 gate。
- 托管产品凭据由 `managed-provider-credentials.ts` 只按 Provider direct pointer + credential owner + adapter 三者一致性解析，并以 Provider→credential 固定锁序、DB-clock 90 秒 lease 与 revision/auth-epoch CAS 做跨实例 singleflight；不存在产品 default 或跨 Provider 共享 live credential。lease loser 有界等待后重读。新签发的长期 grant 若因 post-validation、terminal reauth 或 CAS loser 被丢弃，先写 Provider 专用加密撤销 outbox，再 fence 本地状态；非流式 401 最多强制续期并重放一次，已经发出的流式请求绝不重放。
- `resolveManagedProviderCatalogAccess` 是唯一允许 disabled managed Provider 解密账号凭据的非执行面入口；仍要求 owned pointer、connected 状态、registration 与完整 generation fence，并复用同一 refresh lease/CAS。它只返回规范化目录和安全 generation 字段，绝不返回 bundle、token 或认证 Header；Gateway inference 的 `resolveManagedProviderAccess` 继续严格要求 active。
- `ai_providers.timeout_ms` 对非流式请求限制完整响应时间；对流式请求先限制建连，收到 SSE 后转为滚动网络空闲超时。每个上游数据块（包括 keepalive）都必须刷新空闲期限，流仍活跃时不得因累计总时长超时。
- 托管 Codex Responses 端点在成功响应缺少 `Content-Type` 时，Gateway 仅对 `adapterKind=codex` 且存在响应体的请求进入既有 SSE 解析、协议转换、usage 校验与结算；其他 Provider、空响应体及显式非 SSE 类型仍 fail closed。
- Provider 超时公开为可重试的 `UPSTREAM_TIMEOUT`/HTTP 504；只有无法建立或维持连接的非超时异常才能归类为 `UPSTREAM_CONNECTION_ERROR`。
- 修改限流策略时同步更新 schema migration、现有用户数据 runner、Admin 页面、目录文档与成功/失败回归。
- `/v1/models` 在 exact Runtime capability 可用时额外返回两个 nullable Claude Code Runtime 数值供 Dream 服务端选择；它们不进入 Dream 浏览器模型 DTO，也不替代 Gateway context/output 能力字段。

| `input-token-estimate.ts` | Input estimate | Separates native protocol images from text; cross-protocol requests retain JSON estimates. |
