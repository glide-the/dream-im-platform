# Observability boundary

`capacity.ts` forwards trusted identity and bounded lifecycle observations to the server-owned observer. It exports no credential, body, SQL or user identifier to metric labels. The same business path runs with or without an observer; an observation failure never retries a business operation. Runtime collection, policy, dashboards and operational receipts remain owned by the Notion runbook and server deployment.

`dreamOperationTrace.ts` uses the request-scoped Next trace captured at startup to name the existing server span. It creates child spans for the dispatched handler and selected domain boundaries only when the active span is recording. Metadata consists of registered operation names, source function names, source-relative paths, and static DTO identifiers. The server probe owns export. `dreamOperationTrace.test.ts` verifies registered names, bounded fallback, span completion, and original dispatch results.
