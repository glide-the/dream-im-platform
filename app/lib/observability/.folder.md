# Observability boundary

`capacity.ts` forwards trusted identity and bounded lifecycle observations to the server-owned observer. It exports no credential, body, SQL or user identifier to metric labels. The same business path runs with or without an observer; an observation failure never retries a business operation. Runtime collection, policy, dashboards and operational receipts remain owned by the Notion runbook and server deployment.

`dreamOperationTrace.ts` uses the request-scoped Next trace captured at startup to name the existing server span. Its operation context carries static registry metadata for the handler, shared authentication, DTO validation, transaction, ledger and receipt spans, and any instrumented domain boundaries. Child spans require a registered operation and an active recording span. The server probe owns export. `dreamOperationTrace.test.ts` verifies several business routes, DTO metadata, the original data transaction and bounded fallback.
