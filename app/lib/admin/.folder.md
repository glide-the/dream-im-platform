# app/lib/admin — Folder Contract

- 本目录承载 Admin Session/RBAC 后的服务端资源校验、事务、SQL 与审计；`app/api/admin/**` Route Handler 保持薄层。
- `claude-plugin-marketplaces.ts` 是平台全局 Remote Marketplace 控制面：严格 Zod、精确 capability、HTTPS host allowlist、GitHub API 固定 commit + raw 精确重建声明插件目录（其他允许主机保留 Git）、临时 checkout、immutable revision/entry、批准/阻断与审计；网络超时、远程读取、ref 与内容校验失败保持独立稳定错误。
- `claude-plugin-marketplaces.test.ts` 锁定 URL/ref 校验、GitHub repository 路由、manifest 解析与完整内容 digest；`claude-plugin-marketplaces.integration.test.ts` 以显式开关让公开 Comfy 与 MCP Apps 来源复用同一生产 checkout/inspector，且不写业务数据库。
- Remote Marketplace v1 只接受仓库内相对目录插件 source；符号链接、路径逃逸、凭据 URL、非 allowlist host、并发同步和无完整插件 digest 的批准请求全部 fail closed。
- 同步目录在任务结束后删除；业务表只保存 URL/ref/commit/manifests/digests/validation/policy，不保存临时路径、bucket key 或用户 scope。
- `claude-agent-resources.ts` 是 Claude Agent 资源控制台的唯一服务端边界：固定 setting、strict Zod、DB-clock heartbeat freshness、`system.read/write`、Origin、乐观 revision、行锁与同事务审计；desired 与 Dream snapshot 的四项策略都只接受 JSON/TypeScript 可精确传输的正安全整数，不设任意产品 min/max，内存合计还必须保证 required-headroom bytes 精确；同一 revisioned JSONB 可带 SDK 五值之一或 null 的全局 effort；不接受无限/关闭保护 sentinel；GET 读取与 PATCH 写事务都必须精确验证 observer 与 Runtime capability，PATCH 在任何 desired 写入前 fail closed；400 只向客户端暴露可安全映射的校验 issue，不泄漏 SQL/异常；禁止 Admin 到 Dream HTTP/Bearer、部署或进程控制。
- `mutations.ts` / `resources.ts` 的模型 CRUD 以两个独立 nullable int4 字段维护 compact/context Runtime 配置，并在读写前验证 `dream.claude-code-runtime-config.v1`；写入继续走既有 Origin、RBAC、事务与审计。
- `provider-credentials.ts` 是静态 Provider credential 激活/轮换的 request-memory 验证边界：新 Provider 只允许 disabled 创建并保持 unverified；登记 Model 后，启用或 credential/base URL/authMode/outputTokenParam 变更（即使仍为 disabled）必须携带 expected auth revision，按 `enabled DESC, code, id` 确定选择 Provider model 并发起一次非流式最小请求，成功后才由 `mutations.ts` 在行锁事务中 CAS 切换 effective 密文与 valid metadata。Discovery-only config 与普通运营字段不触发认证验证。
- candidate 验证失败、缺少模型/凭据或 revision 冲突只追加脱敏审计并保留旧 effective；Secret、Authorization header 和响应正文不得进入响应、错误或 audit metadata。存量 active/unverified 继续由 Gateway 使用，validation status 不是运行准入条件。
- `provider-config-safety.ts` 统一拒绝新 config 中递归出现的 credential/secret/token/password/cookie/authorization-like key，并在 Provider list/detail、写响应和历史 audit 出口递归移除兼容脏数据；它不改写数据库，也不改变 Gateway 内部读取的 raw config。
- `provider-managed-auth.ts` 是 Codex、xAI、GitHub Copilot 单账号 Provider 的 Admin 编排边界：每个 managed Provider 最多直接拥有一个 live credential，同产品第二个账号必须新建 Provider；start/poll/cancel/reauth/disconnect/retry 全部执行 strict Zod、Origin、RBAC、epoch/revision/actor/DB-clock lease fencing、事务与审计，Route Handler 不承载业务逻辑。
- 托管 Device 流只持久化加密后的完整临时状态；浏览器投影仅含 user code、verification URL、期限、失败码与无 Secret 的撤销任务状态。status 返回最新 attempt（包括终态）；可重试网络/5xx 在 expiry 前保持 pending 并按上游 interval/slow_down 安排 nextPollAt；`starting` 与 poll 均有 90 秒可恢复 lease。任何已签发但因身份、scope、readiness、事务或 CAS 被拒绝的长期 grant，必须先持久化产品最小撤销材料，再清除临时状态。断开在同一事务中先写加密撤销任务、停用 Provider 并清除 effective；任务失败保留密文并允许 revision-fenced 手工重试，远端 outcome 如实记录为 `pending/succeeded/failed/unsupported/not_attempted`。
- 托管 Provider 的 Endpoint、Client registration 与集成身份属于服务端 product registry；Codex/xAI/Copilot 默认值固定随版本发布，环境变量仅作高级覆盖，Admin CRUD 不接受 Endpoint、API Key 或 authMode。Provider 创建固定 disabled；启用前必须同时存在 connected managed credential、enabled model 与有效 pricing。
- `provider-discovery.ts` 同时编排 generic 静态凭据目录和三种 managed 产品目录；托管账号连接事务提交后才自动创建目录 snapshot，失败不得回滚凭据。snapshot generation 绑定 Provider/auth/account/credential revision 与 registration fingerprint，`catalog_hash` 参与 PostgreSQL advisory transaction lock 去重，Apply 时必须重算并复验。新增 Model 恒为 disabled，不创建 Pricing；既有 Model 只刷新 discovery metadata；缺失、冲突或 Gateway 不兼容条目不得自动停用、删除或应用。
- 历史 `managed_account_binding_mode` 只作为 schema 兼容字段：managed Provider 恒为内部 `pinned`，generic 恒为 NULL；Admin 不提供 default/binding/账号池操作，status 即使保留兼容 DTO 也只能返回 URL Provider 自己的一个账号且 `defaultAccount=null`。
- Provider “删除”使用不可恢复的控制面 tombstone：严格 body 携带服务端投影的 opaque `expectedDeleteRevision`，事务内锁定 Provider 并重复检查全部 Model 与间接 Pricing 计数；任一依赖存在返回 `PROVIDER_DELETE_BLOCKED_BY_DEPENDENCIES`，不得级联删除。connected 账号、进行中授权或未完成撤销必须先通过原生命周期安全收口；成功后清除静态 Secret、递增 auth revision/epoch、从 list/detail 隐藏，同时保留 Usage、计费、撤销与审计引用。
- status 与启用门禁都必须用当前部署 key 实际解密 connected envelope，并通过严格 token schema 与 adapter product 一致性校验；数据库行状态或 key 长度本身不能代表 Gateway 可用，失败只投影安全原因。加密 key 不可用时 status 必须返回稳定、无 Secret 的 readiness reason，供 Admin 解释为何添加账号动作不可执行。
- `guard.ts` 对所有 mutation 始终要求 Origin；缺失、非法或不在 request origin/显式 allowlist 中一律 403，不按部署环境名称降级。
