`config.ts` validates exact configured issuer/origins/resources and per-deployment confidential client/redirect/background scopes, including the explicit `reflections:execute` worker scope. Dream browser form entry accepts any supplied browser Origin and reflects it for credentialed CORS; successful entry returns to that initiating Origin. Local and public Dream deployments register separate OAuth/service clients in `DREAM_DATA_SERVICE_CLIENTS`, while both resolve the same canonical Dream user domain. `server.ts` owns Better Auth Google/OAuth/JWT/device composition and schema capability checks. `oauthClientCatalog.ts` registers browser/device public clients and a distinct hashed-secret `client_credentials` client for each Dream deployment. `serviceIdentity.ts` verifies the service OAuth token and distinguishes service-only `Authorization` from the server-only dual-Bearer user form; legacy static service headers are rejected. Subject links reference existing canonical Dream users; a login session alone never grants Admin permissions. All identity persistence is Admin owned; missing secrets/capabilities fail closed.

Protocol: [shared contract](../../../docs/architecture/admin-dream-auth-data-contract.md). Runtime and filesystem execution remain Dream owned. Better Auth rethrows unknown plugin and ORM failures to the outer transaction boundary, which rolls back and returns a generic no-store 503. Internal data ingress logs only the request ID plus allowlisted error name, PostgreSQL code, constraint and stack call sites; it never logs exception messages/objects, tokens, authorization/device codes, credentials or request bodies.

- `database.ts` requires explicit auth/control PostgreSQL credentials and exact identity ledger version/hash; no startup DDL. Physical catalog/role evidence remains a separate required gate.
- `adminSessionRepository.ts`, `adminAuthService.ts`, `adminAuthHandler.ts` provide独立Admin operator登录/logout/bootstrap：只验证`admin_users`，在同一Drizzle UOW创建或撤销`admin_sessions`、更新login timestamp、写安全audit并实时读取RBAC。Dream Better Auth Session、OAuth token、canonical user和subject link均不能授权管理路由。
- `adminPasswordRecovery.ts` 与 `scripts/reset-admin-password.ts` 提供本机锁定恢复：默认dry-run只确认active Admin目标；显式apply从隐藏TTY读取两次新密码，经control credential在一个Drizzle事务中锁定`admin_users`、替换scrypt hash、撤销该管理员全部现存Session并写不含密码/hash的audit。它不读取或修改Dream user、Better Auth account或subject link。
- `SubjectRepository` invokes the forward-Drizzle controlled canonical registration function, verifies exact registration capability and preserves original Free/default-model initialization; auth receives no direct canonical/ledger/subscription writes.
- `BrowserSessionService` stores encrypted per-service/origin OAuth bundles and recovers the original exchange, serializes refresh, commits login-required diagnostics on failed renewal.
- `delegation*` owns hashed/encrypted recovery with mutually exclusive `server-persistence` (dream read/write), `gateway-cli` (Gateway three scopes), and `editor-stdio` (editor read/write) purposes. Editor binds owned `user_sessions.id`; thread/optional run+workspace, active subject and Gateway key are rechecked on resolve/renew. Story confirmation grants bind the Admin-owned message/claim and require the same `dispatching` claim plus an unexpired database-clock lease. A claim recovery revalidates that source, active subject, exact entity ownership, stored row and encrypted result in the current UOW, then returns the original grant without recursively acquiring its row lock after the claim-message lock; normal delegated reads keep the grant→message order, so the two paths cannot form a lock cycle. Reflections may exchange one live service/subject/task/section/Thread-bound `rta_` for a separate `gateway-cli` delegation; every resolve/renew revalidates the source authority and terminal aggregate, and the source bearer is never the child credential. Creation appends safe audit; renew/revoke use same-UOW receipts. Renewal never widens scope/entity; Session switches require a fresh OAuth-authorized grant. This does not replace complete Workflow activation authorization.
- `serviceAccessToken` independently binds active OAuth grants to the verified service's browser or explicitly configured device client. OAuth-only handlers and receipt recovery reject `idg_` and `rta_` opaque bearers with 403 before JWT parsing or subject lookup; Thread/Run/Editor handlers continue through their explicit authority boundaries.
- `delegationContracts` advertises four implemented special routes with actual method/path/input/output version/hash only after exact identity/delegation/purpose and unified-domain requirements exist. New creation compares the complete authoritative Workflow Thread context; original creation recovery and existing-grant resolution retain original entity ownership for final persistence. `capabilities.auth.delegations` is independent of data operation discovery; special routes are never generic-dispatched. Original-ID public action recovery reads only its bounded committed response even after expiry/revocation; it does not resolve new authority, and absent+expired renewal fails closed.
- `pageContext`, `browserRedirect`, official provider client and `app/auth` preserve signed OAuth/Google/device continuation, display client/scope/resource, and keep access/refresh credentials out of the browser.
- `oauthClientCatalog` derives the resource, browser client(s), device client and exclusive client-resource links from the same validated runtime configuration. The release CLI defaults to a read-only plan; only explicit `--apply` reconciles these rows through Drizzle, removes obsolete links for those controlled clients and verifies the resulting catalog. Unlinked historical resource rows remain retained; dynamic registration remains disabled.
- `legacyCredentialAdoption*` accepts one exact active canonical Dream user and pinned source fingerprint, derives opaque identity/account IDs, and uses one typed Drizzle transaction to preserve the original supported password hash in a Dream credential account plus subject link. It never reads or creates Admin membership, never changes the legacy row, defaults to dry-run and rejects every partial or conflicting target.
