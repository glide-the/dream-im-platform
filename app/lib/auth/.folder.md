# Admin authentication domain

`config.ts` validates exact configured issuer/origins/resources and per-service credential/client/redirect/background scopes, including the explicit `reflections:execute` worker scope. `server.ts` owns Better Auth Google/OAuth/JWT/device composition and schema capability checks. Subject links reference existing canonical users; a login session alone never grants Admin permissions. All identity persistence is Admin owned; missing secrets/capabilities fail closed.

Protocol: [shared contract](../../../docs/architecture/admin-dream-auth-data-contract.md). Runtime and filesystem execution remain Dream owned. Better Auth rethrows unknown plugin and ORM failures to the outer transaction boundary, which rolls back and returns a generic no-store 503 without logging exception objects. Never log tokens, codes, credentials or request bodies.

- `database.ts` requires explicit auth/control PostgreSQL credentials and exact identity ledger version/hash; no startup DDL. Physical catalog/role evidence remains a separate required gate.
- `adminIdentityRepository.ts`, `adminAuthService.ts`, `adminAuthHandler.ts` provide sole Better Auth Admin Session login/logout/bootstrap, explicit active Admin membership and live RBAC with same-UOW safe audit. Ordinary Session without membership is 403; missing Session is 401. Legacy HMAC cookie issuer/lookup is retired; historical rows require explicit adoption/revocation.
- `SubjectRepository` invokes the forward-Drizzle controlled canonical registration function, verifies exact registration capability and preserves original Free/default-model initialization; auth receives no direct canonical/ledger/subscription writes.
- `BrowserSessionService` stores encrypted per-service/origin OAuth bundles and recovers the original exchange, serializes refresh, commits login-required diagnostics on failed renewal.
- `delegation*` owns hashed/encrypted recovery with mutually exclusive `server-persistence` (dream read/write), `gateway-cli` (Gateway three scopes), and `editor-stdio` (editor read/write) purposes. Editor binds owned `user_sessions.id`; thread/optional run+workspace, active subject and Gateway key are rechecked on resolve/renew. Creation appends safe audit; renew/revoke use same-UOW receipts. Renewal never widens scope/entity; Session switches require a fresh OAuth-authorized grant. This does not replace complete Workflow activation authorization.
- `serviceAccessToken` independently binds active OAuth grants to the verified service's browser or explicitly configured device client. OAuth-only handlers and receipt recovery reject `idg_` and `rta_` opaque bearers with 403 before JWT parsing or subject lookup; Thread/Run/Editor handlers continue through their explicit authority boundaries.
- `delegationContracts` advertises four implemented special routes with actual method/path/input/output version/hash only after exact identity/delegation/purpose and unified-domain requirements exist. New creation compares the complete authoritative Workflow Thread context; original creation recovery and existing-grant resolution retain original entity ownership for final persistence. `capabilities.auth.delegations` is independent of data operation discovery; special routes are never generic-dispatched. Original-ID public action recovery reads only its bounded committed response even after expiry/revocation; it does not resolve new authority, and absent+expired renewal fails closed.
- `pageContext`, `browserRedirect`, official provider client and `app/auth` preserve signed OAuth/Google/device continuation, display client/scope/resource, and keep access/refresh credentials out of the browser.
