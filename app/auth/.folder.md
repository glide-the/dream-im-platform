# Unified authentication pages

<!-- [Sync] 2026-10-09: keep Images authorization in the existing OAuth consent experience. -->

`sign-in`, `consent` and `device` provide the Admin-owned login and OAuth/device authorization experience. `dream/password` and `dream/google` accept the restored Dream product form only from an exact configured Dream origin, then invoke the same Better Auth 1.7.4 email/social APIs and return to Dream's PKCE entry. Password registration and account-selectable Google login remain available. Consent display validates provider-signed context and registered client data; actual grants always go through the provider endpoint.

The browser receives no service secret or API token. Device approval retains the installed pending/approved/denied state machine. Admin management permissions remain independent of login. See [contract](../../docs/architecture/admin-dream-auth-data-contract.md).

`consent/AuthConsent.tsx` presents `images:create` as the user-facing ability to generate/edit images with usage billing; it does not create a separate consent or identity path.
