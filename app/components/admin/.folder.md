# Admin components contract

- 本目录只承载管理端交互与 Refine 数据编排；服务端授权、校验、事务和审计必须留在 `app/lib/**`。
- `SubscriptionLifecycleManager.tsx` 的首次开通与既有订阅生命周期动作必须分开：既有订阅换套餐走下周期 `upgrade/downgrade`，取消走 `cancel_at_period_end`，不得用重复创建模拟切换。
- 可调用订阅行必须明确展示“更换套餐”和“期末取消”；高风险动作仍通过带原因的确认 Dialog 提交，客户端按钮隐藏不作为授权边界。
- 修改组件时复用现有 Admin chrome、设计 Token、可访问 label/focus 和服务端分页合同，并同步更新对应交互文档与测试。
- `StoryWorkflowRunsResourceView` 与 Story 列表显示同一 Dream 工作空间标题：优先 canonical Story/Project title，只有 Project 尚未形成时才回退 launch goal 前缀；Admin 不写该标题。
- `ClaudePluginMarketplaceManager.tsx` 只管理平台全局远程来源、临时同步 revision 与 entry 批准/阻断；不创建用户 Marketplace、不上传对象存储桶，并显示 commit/manifest/完整插件 digest 审阅证据。
- `ClaudeAgentResourceConsole.tsx` 每 10 秒用可取消查询读取 PostgreSQL 投影，展示 heartbeat/sample freshness、desired/effective/revision、进程/cgroup/pipeline 闭集；null 与 stale 准入值显示“未知”；最大并发允许 `1..2_147_483_647`，不提供 0/null 无限语义；无效草稿在客户端阻断且不发 PATCH，成功后立即投影 desired/pending，随后用 Dream 定时写回的 effective 自动收敛为 applied；只保存带 expected revision 的 desired policy，不生成 AutoDL 投影或提供进程控制，生效无需重启。
