# Admin components contract

- 本目录只承载管理端交互与 Refine 数据编排；服务端授权、校验、事务和审计必须留在 `app/lib/**`。
- `SubscriptionLifecycleManager.tsx` 的首次开通与既有订阅生命周期动作必须分开：既有订阅换套餐走下周期 `upgrade/downgrade`，取消走 `cancel_at_period_end`，不得用重复创建模拟切换。
- 可调用订阅行必须明确展示“更换套餐”和“期末取消”；高风险动作仍通过带原因的确认 Dialog 提交，客户端按钮隐藏不作为授权边界。
- 修改组件时复用现有 Admin chrome、设计 Token、可访问 label/focus 和服务端分页合同，并同步更新对应交互文档与测试。
- `StoryWorkflowRunsResourceView` 与 Story 列表显示同一 Dream 工作空间标题：优先 canonical Story/Project title，只有 Project 尚未形成时才回退 launch goal 前缀；Admin 不写该标题。
- `ClaudePluginMarketplaceManager.tsx` 只管理平台全局远程来源、临时同步 revision 与 entry 批准/阻断；不创建用户 Marketplace、不上传对象存储桶，并显示 commit/manifest/完整插件 digest 审阅证据。
- `ClaudeAgentResourceConsole.tsx` 每 10 秒用可取消查询读取 PostgreSQL 投影，展示 heartbeat/sample freshness、desired/effective/revision、进程/cgroup/pipeline 闭集；null 与 stale 准入值显示“未知”；四项策略都接受正安全整数且无任意产品 min/max，不提供 0/null 无限/关闭保护语义，内存合计只受 required-headroom bytes 可精确表达的技术边界；独立 Runtime 区域只维护可空的全局 effort，正常字段不显示重复范围说明，客户端或可识别 API 400 只显示字段级简短错误并阻断重复 PATCH；显式保存按钮直接提交且不使用原生 `confirm/alert/prompt`，成功后立即投影 desired/pending 并主动重取 desired/revision/updatedAt，随后用 Dream 定时写回的 effective 自动收敛为 applied；只保存带 expected revision 的 desired policy，不生成 AutoDL 投影或提供进程控制，生效无需重启。
- `AdminResourceViews.tsx` / `AIModelRegistry.tsx` 在模型域单独维护可空的 Claude Code 自动压缩窗口和最大上下文 Token；两项不复用 Gateway `context_window/max_output_tokens`，空值表示不设置，页面不展示底层 env 名或新增运行操作。
- AIModelRegistry 的真实新增/编辑路由必须把 `claude-runtime` section 传给 `AdminResourceFormPage`；只在通用字段表声明字段但不接入独立页面不算完成。
