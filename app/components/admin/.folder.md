# Admin components contract

- 本目录只承载管理端交互与 Refine 数据编排；服务端授权、校验、事务和审计必须留在 `app/lib/**`。
- `SubscriptionLifecycleManager.tsx` 的首次开通与既有订阅生命周期动作必须分开：既有订阅换套餐走下周期 `upgrade/downgrade`，取消走 `cancel_at_period_end`，不得用重复创建模拟切换。
- 可调用订阅行必须明确展示“更换套餐”和“期末取消”；高风险动作仍通过带原因的确认 Dialog 提交，客户端按钮隐藏不作为授权边界。
- 修改组件时复用现有 Admin chrome、设计 Token、可访问 label/focus 和服务端分页合同，并同步更新对应交互文档与测试。
- `StoryWorkflowRunsResourceView` 与 Story 列表显示同一 Dream 工作空间标题：优先 canonical Story/Project title，只有 Project 尚未形成时才回退 launch goal 前缀；Admin 不写该标题。
- `ClaudePluginMarketplaceManager.tsx` 只管理平台全局远程来源、临时同步 revision 与 entry 批准/阻断；不创建用户 Marketplace、不上传对象存储桶，并显示 commit/manifest/完整插件 digest 审阅证据。同步进度读取既有持久化 run、跨刷新恢复；失败显示稳定错误、原因与重试，不用静默 disabled button 代替反馈。
- `ClaudeAgentResourceConsole.tsx` 每 10 秒用可取消查询读取 PostgreSQL 投影，展示 heartbeat/sample freshness、desired/effective/revision、进程/cgroup/pipeline 闭集；null 与 stale 准入值显示“未知”；四项策略都接受正安全整数且无任意产品 min/max，不提供 0/null 无限/关闭保护语义，内存合计只受 required-headroom bytes 可精确表达的技术边界；独立 Runtime 区域只维护可空的全局 effort，正常字段不显示重复范围说明，客户端或可识别 API 400 只显示字段级简短错误并阻断重复 PATCH；显式保存按钮直接提交且不使用原生 `confirm/alert/prompt`，成功后立即投影 desired/pending 并主动重取 desired/revision/updatedAt，随后用 Dream 定时写回的 effective 自动收敛为 applied；只保存带 expected revision 的 desired policy，不生成 AutoDL 投影或提供进程控制，生效无需重启。
- `AdminResourceViews.tsx` / `AIModelRegistry.tsx` 在模型域单独维护可空的 Claude Code 自动压缩窗口和最大上下文 Token；两项不复用 Gateway `context_window/max_output_tokens`，空值表示不设置，页面不展示底层 env 名或新增运行操作。
- AIModelRegistry 的真实新增/编辑路由必须把 `claude-runtime` section 传给 `AdminResourceFormPage`；只在通用字段表声明字段但不接入独立页面不算完成。
- 通用 Provider 表单只展示 static credential capability、configured、effective auth revision 与当前 revision 的 validation status/time；已保存 Secret 永不回填。新建时禁止 active，流程固定为 disabled → Model → enable；此后启用或认证相关轮换（包括 disabled Provider）由服务端确定选择 Model 并在验证成功后切换，UI 不提供验证 Model selector；失败/409 保留草稿并明确旧 effective 是否仍生效。
- 托管产品 Provider 只允许 Codex、xAI 与 GitHub Copilot 三种显式类型；一条 Provider 只连接一个产品账号，同产品多账号必须创建多条 Provider。新建表单不展示或提交 Endpoint、静态 API Key、authMode，保存后进入编辑页的单账号面板。面板只读取服务端脱敏投影，可显示短期 user code/verification URL，但不得接收 Device Code、Access/Refresh Token 或产品 Client Secret。
- `ProviderManagedAuthPanel.tsx` 始终以产品文案展示当前 Provider 的连接账号入口（ChatGPT/xAI/GitHub）；已有账号只允许重新授权或断开，不展示产品账号池、默认账号、Provider binding 或“添加其他账号”。内置产品元数据就绪时可直接发起 Device Flow，显式覆盖或服务端 secret/Endpoint gate 无效时才禁用并解释前置。面板同时展示代码、产品配置、加密、Endpoint policy 与 Gateway effective 五类状态；账号 connected 与 Provider active/effective 必须分开表达。轮询遵守服务端 nextPollAt，并对 409 lease contention 与 429 too-early 使用有界退避；只有发起管理员可自动/手工 poll 或 cancel，过期 `starting` 可安全重新发起。失败的重新授权只能作为历史状态展示，并明确不会覆盖仍有效的当前账号；撤销任务只展示安全状态/失败码，`pending/failed` 提供 revision-fenced 重试；disconnect 是会停用 Provider 并清除本地凭据的高风险动作，保留明确确认。
- 托管账号连接成功后，面板读取服务端返回的 `catalogSync`：成功进入现有 snapshot diff review，失败仍显示账号已连接并提供“同步模型”重试。Provider 卡片对已连接的 managed Provider 同样显示同步入口；上游未提供安全账号标签时显示“账号：已连接”，不得误报“未连接”。`ProviderDiscoveryReview` 将当前 Gateway 不兼容的产品模型作为只读 `unsupported` 条目展示，不能勾选；Apply 后的新模型仍为 disabled，Pricing 独立配置。
- `ProviderDeleteAction.tsx` 是 Provider 列表与设置页共用的删除交互：只保留一次风险确认；先由服务端检查 Model/Pricing，再在必要时通过既有 managed-auth API 安全断开账号，最后提交带 opaque `expectedDeleteRevision` 的 DELETE。409 必须保留对话框并显示依赖数量与“先删除 Pricing 和模型”的恢复路径；客户端计数只用于解释，不能代替服务端门禁。
- `provider-fields.ts` 是 Provider 新建、编辑与列表共用的 server/client-neutral 字段元数据；Server page 不得从 `"use client"` 的 `AdminResourceViews.tsx` 展开运行时数组。
- Provider UI 不提供通用 Secret/环境变量入口；Bearer 文案必须说明其只是静态 header 格式。状态不只依赖颜色，验证进度/失败使用可访问 status/alert。
- `credentialUsable` 来自服务端真实 envelope 解密校验；UI 不可仅凭 connected 行或 key 配置存在显示“当前生效”。Copilot 指标表达已保存凭据，不声称实时探测远端 entitlement。
