- 脚本必须显式区分应用 DSN 与 migration DSN；需要迁移的隔离测试必须让 `DATABASE_URL`、`TEST_DATABASE_URL` 和 `MIGRATION_DATABASE_URL` 指向同一个具名、可删除目标。
- `check-chat-input-queue-readiness.mjs` 只读取 `DREAM_DATA_DATABASE_URL` 指向的库，要求 `EXPECTED_DATABASE_NAME` 精确匹配；队列/任务表、capability 版本与合同 hash 或当前数据角色的表/序列权限缺失时输出 `not_ready` 并以 2 退出。发布前须在真实目标库运行该检查；它不执行 migration，也不写业务数据。
- `check-chat-task-result-readiness.mjs` 以同一具名数据库和 Dream 数据角色检查 `dream.chat-task-result.v1` 的合同 hash、0068 表/列/单消费者索引/ACL，并核对 `INK_ADMIN_DREAM_SERVICE_CLIENT_ID` 对应的 `DREAM_DATA_SERVICE_CLIENTS` 注册含 `task-return:dispatch`；只输出缺失项代码，不输出密钥或消息正文。状态为 `not_ready` 时以 2 退出；它不执行 migration、OAuth provisioning 或业务写入。
- `probe-task-session-pre-result.ts` 由同一个隔离 runner 在仅迁移至 0067 时调用生产 Chat operation service：验证普通任务创建、同键重放、读取、领取及目标最终助手消息持久化仍可执行，`create-returning` 因缺 0068 capability 明确拒绝且不新增任务行。随后 runner 前向应用 0068，再执行完整结果交接 probe；不修改正常库。
- `probe-task-result-route.ts` 只在 `run-chat-input-queue-contract.mjs` 创建的具名隔离库上运行；签发本轮临时 ES256 OAuth 令牌并调用生产 Route Handler，验证无令牌拒绝、缺 scope 拒绝、单次领取、同一调用恢复授权、来源 claim 授权只读取自身 Workflow context 和绑定的 Deck/Voice、已核实来源 final 后结算及终态禁止重领。脚本不访问正常账户或真实模型。
- 当前 Dream 通过父轮次内的 `wait_threads` 等待目标 Thread，不再提供公开 `task-results` 路由或后台 `TaskResultCoordinator`。本目录不设置 `DREAM_REPO_ROOT`，也不把已删除的跨仓库后台交付路径作为 Admin 验收。Dream 的等待与 final 回传由 Dream 仓库自己的公开生产入口测试。
- `next-config.test.mjs` 同时固定两条本地入口：`pnpm dev` 保留 Webpack HMR；`pnpm local:stable` 先 build，再由既有 PostgreSQL supervisor 执行 `next start`，供 Dream 高频后台 DTO 联调使用。两者执行同一应用合同且都不隐式迁移数据库。
- 禁止让测试 harness 回退读取 `.env.local` 的共享 migration credential，也禁止迁移、清空或删除无法证明归属的数据库。
- 临时 PostgreSQL、端口、进程、构建目录与测试产物必须由脚本创建、记录所有权并在 `finally` 中只清理自身资源。
- `run-chat-scheduled-task-contract.mjs` builds the DB package, creates and identity-checks a randomly named `ink_scheduled_chat_test_*` embedded PostgreSQL database, applies the current Admin migration workflow, and runs the production scheduled Chat integration test. It proves ordinary TaskSession source/created links remain while trigger-owned sessions are excluded; `finally` stops and removes only its own cluster.
- 修改脚本时保留生产入口与真实 DTO/协议，不得在应用模块加入 test-only 行为、SQLite 或内存回退。
- `activate-unified-auth-data-access.mjs` 是唯一正常库角色/ACL激活入口：默认dry-run；v2 manifest同时绑定 Admin/Dream commit，并要求 `AUTH_DATA_DREAM_RELEASE_DIR` 与当前 Admin checkout 都是对应精确HEAD且tracked-clean。apply必须同时提供 `--production-approval`、私有0600 `AUTH_DATA_CUTOVER_CONFIG`、校验通过的停机备份、精确database/port/data directory、完整migration/capability、active canonical Gateway binding和四角色合同。它只创建三个NOINHERIT LOGIN服务role与一个Dream NOLOGIN role，复用共享ACL计划并执行实际credential/allow/deny probes；Admin探针必须覆盖credential列、Session写入、RBAC读取、audit写入并确认两角色不能读取`identity.admin_subject_links`；不得由应用启动或migration隐式调用。
- `rotate-dream-gateway-service-key.ts` 默认只输出脱敏 scope drift；显式 `--force` 允许同scope泄露事件也进入rotate计划，仍需`--apply`才通过严格DTO、领域服务和Drizzle transaction原子撤销旧canonical-subject key、创建新key、写审计，并把一次性明文只替换到显式传入且验证为普通mode-0600文件的Dream backend env。数据库提交失败时恢复原env，脚本与回执不得打印key、hash或pepper。
- 数据迁移 E2E 的 direct-SQL active Provider 明确模拟存量 effective 行：0044 后保持 active、auth revision 1、unverified；不得为通过新 Admin active-create 合同而伪标 valid 或增加生产 bypass。
- Provider managed-account 历史迁移先运行 `pnpm exec tsx drizzle/data/provider-managed-accounts.ts` 检查脱敏 dry-run；确认 revocation job 已排空后，只有显式 `--apply` 才提交 account AAD/HMAC/binding/attempt cutover 和 registry 收据。
- 根 `pnpm db:migrate` 与命名兼容入口都调用 `migrate-provider-managed-accounts.mjs`；该脚本先做无数据库 preflight，再只编排编译后的 DB 工具，固定执行 0047 → managed-account data → 0048、0049 → provider-owned data → 0050、0051 → deleted-Provider orphan data → 0052 → check。orphan runner 仅本地断开和擦除 Secret，回执固定 `remoteRevocation=not_attempted`。编排器只解析并持有一次目标数据库生命周期，再把同一 DSN 传给全部子阶段，失败可从已提交前缀安全续跑。
- `run-provider-managed-auth-e2e.mjs` 默认在断言后立即清理；Chrome 插件人工复核可显式设置 `INK_MANAGED_AUTH_E2E_HOLD_SECONDS=1..300`，仅在自动断言与 Secret 扫描通过后短暂保留 runner 自有现场。
- 同一 managed-auth runner 在账号/Gateway 验证后复用已认证 Admin，独立运行 Provider 删除 E2E；它只删除自己创建的零依赖 Provider，关联 Model/Pricing 的 Provider 必须保持不变。
- 根 `migrate.mjs` 与 `lib/migration-journal.mjs` 只允许作为兼容 facade；migration 计划、连接目标和执行权属于 `packages/db/src/**`。
- `seed-default-dream-plans.mjs` 可从 enabled、Provider credential 完整且具有有效
  `free/default` Pricing 的模型自举首个 Free Entitlement；若最新 published Free
  snapshot 的默认模型已停用或策略指定了另一模型，只能新增并发布后继 Version，
  不得修改历史 snapshot。未受管的 draft 必须阻断自动发布。
