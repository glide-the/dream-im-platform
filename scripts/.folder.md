# Validation and operations scripts contract

- 脚本必须显式区分应用 DSN 与 migration DSN；需要迁移的隔离测试必须让 `DATABASE_URL`、`TEST_DATABASE_URL` 和 `MIGRATION_DATABASE_URL` 指向同一个具名、可删除目标。
- 禁止让测试 harness 回退读取 `.env.local` 的共享 migration credential，也禁止迁移、清空或删除无法证明归属的数据库。
- 临时 PostgreSQL、端口、进程、构建目录与测试产物必须由脚本创建、记录所有权并在 `finally` 中只清理自身资源。
- 修改脚本时保留生产入口与真实 DTO/协议，不得在应用模块加入 test-only 行为、SQLite 或内存回退。
- 数据迁移 E2E 的 direct-SQL active Provider 明确模拟存量 effective 行：0044 后保持 active、auth revision 1、unverified；不得为通过新 Admin active-create 合同而伪标 valid 或增加生产 bypass。
- Provider managed-account 历史迁移先运行 `pnpm exec tsx drizzle/data/provider-managed-accounts.ts` 检查脱敏 dry-run；确认 revocation job 已排空后，只有显式 `--apply` 才提交 account AAD/HMAC/binding/attempt cutover 和 registry 收据。
- 根 `pnpm db:migrate` 与命名兼容入口都调用 `migrate-provider-managed-accounts.mjs`；该脚本先做无数据库 preflight，再只编排编译后的 DB 工具，固定执行 0047 → managed-account data → 0048、0049 → provider-owned data → 0050、0051 → deleted-Provider orphan data → 0052 → check。orphan runner 仅本地断开和擦除 Secret，回执固定 `remoteRevocation=not_attempted`。编排器只解析并持有一次目标数据库生命周期，再把同一 DSN 传给全部子阶段，失败可从已提交前缀安全续跑。
- `run-provider-managed-auth-e2e.mjs` 默认在断言后立即清理；Chrome 插件人工复核可显式设置 `INK_MANAGED_AUTH_E2E_HOLD_SECONDS=1..300`，仅在自动断言与 Secret 扫描通过后短暂保留 runner 自有现场。
- 同一 managed-auth runner 在账号/Gateway 验证后复用已认证 Admin，独立运行 Provider 删除 E2E；它只删除自己创建的零依赖 Provider，关联 Model/Pricing 的 Provider 必须保持不变。
- 根 `migrate.mjs` 与 `lib/migration-journal.mjs` 只允许作为兼容 facade；migration 计划、连接目标和执行权属于 `packages/db/src/**`。
- `seed-default-dream-plans.mjs` 可从 enabled、Provider credential 完整且具有有效
  `free/default` Pricing 的模型自举首个 Free Entitlement；若最新 published Free
  snapshot 的默认模型已停用或策略指定了另一模型，只能新增并发布后继 Version，
  不得修改历史 snapshot。未受管的 draft 必须阻断自动发布。
