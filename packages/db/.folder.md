# packages/db — Folder Contract

- 本包按 Paperclip 的 workspace DB package 方式集中拥有 PostgreSQL client、内嵌 PostgreSQL 生命周期、Drizzle schema 与显式 migration runner。
- `src/schema/**` 是 Admin、Gateway、Billing 与 Dream 共享 PostgreSQL schema 的唯一 TypeScript 来源；根目录 `drizzle/**` 继续作为不可变的 SQL/journal/snapshot 历史，迁移内容、tag、when 与 hash 不因包结构调整而改变。
- `pnpm db:generate` 先编译 NodeNext schema，再让 Drizzle Kit 读取 `dist/schema/index.js` 与 `dist/schema/dream.js`；这样保留源文件正确的 `.js` import 合同，同时避免 Drizzle 的 CommonJS source loader 错误吞掉 `MODULE_NOT_FOUND`。
- 内嵌 PostgreSQL 只初始化 cluster/database 并管理进程，不创建业务表；业务 DDL 只允许由 `src/migrate.ts` 在发布阶段显式执行。应用启动不得自动迁移。
- `MIGRATION_DATABASE_URL` 仍优先指向显式外部目标；缺少该变量时，只有显式 `INK_DATABASE_MODE=embedded-postgres` 才能启动本包管理的数据库。
- `dist/provider-managed-accounts-data.js` 是 Provider expand→data→contract 发布流程的 compiled CLI；无数据库 preflight 先验证 Secret 配置，实际 dry-run/apply 与 `src/migrate.ts` 共用 `resolveMigrationConnection()`，并把解析后的单一目标注入 `drizzle/data/provider-managed-accounts-core.ts`，执行后始终释放 package-owned embedded PostgreSQL。
- `dist/provider-owned-credentials-data.js` 只把 0049 后的 effective account binding 收敛为直接 Provider ownership；它复用同一 migration target，默认 dry-run，且不复制、删除或重加密 live token envelope。
- `dist/provider-deleted-credential-orphans-data.js` 执行 0051/data/0052 本地失效阶段；它复用同一 migration target，默认 dry-run，只擦除 deleted/missing/mismatched owner 的 live credential 与相关 active attempt Secret，并明确记录远端撤销未尝试。
- 容器内 PostgreSQL 可监听私有 Compose 网络供 Dream 使用，但部署文件不得把 5432 暴露到公网。
- Dream-managed MCP 资源由四张 Admin-owned 关系承载；凭据表不重复用户身份且只存密文，成功导入指纹在目标 Server 删除后仍保持唯一。
- 每个 Dream MCP 连接的 App 用户偏好作为 `dream_mcp_servers` 上 deny-by-default 的 additive 列保存，并使用独立 revision；Dream 不得把设置变化混入连接配置、凭据或 discovery revision。
- Claude Agent 资源观测只使用 `claude_agent_resource_snapshots` latest-instance 表；JSON 只承载内容无关进程指标，实例/heartbeat/sample 时间由关系列承载。
- Claude Code Runtime 模型配置只使用 `ai_models` 的两个 nullable positive int4 列；全局 effort 留在 revisioned resource-policy JSONB。0041 是唯一 additive DDL/capability 发布者。
- Chat 历史分页只使用 0042 的稳定顺序 B-tree；`parts`/`metadata` 大字段不进入 covering index，Dream 只在 exact capability 已发布后启动。
- Chat assistant final 投影由 0043 的三个 additive 列承载；完整过程仍以不可变 `parts` 为 canonical，历史回填只能通过 Admin 显式 runner 执行。
