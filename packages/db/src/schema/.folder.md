# Canonical PostgreSQL schema

This folder is the only Drizzle schema source. `index` owns canonical/shared control tables, `dream` preserves adopted legacy domain structures, `auth-generated` declares the exact pinned Better Auth protocol tables, `auth` declares explicit identity bindings/encrypted BFF/runtime/domain receipts. Generated SQL/journal/snapshots are immutable; forward changes only. Current auth role is granted controlled canonical registration function execution through explicit isolated ACL validation, never canonical/body/ledger writes.

`public.deck_versions` retains its existing JSONB projection and historical content hash while new versions also store nullable `snapshot_canonical_json` text. The projection CHECK and independent capability protect exact new canonical bytes; NULL legacy records are not guessed or rewritten. Forward 0059 preserves all earlier history.

`auth.workflowPreflightRequests` physically owns `dream.workflow_preflight_requests`: immutable original service/subject/request/input/PF/owner/workspace evidence, with PF RESTRICT FK and no workspace/canonical FK that would constrain unrelated historical deletion. Forward0060 guards UPDATE/DELETE/TRUNCATE and grants data only SELECT/INSERT through explicit ACL deployment. Lifecycle remains solely in original `public.workflow_preflights`; this association is not a job or secondary state machine.

Forward 0061 is an unregistered Reflections aggregate candidate. `public.reflection_task` adds nullable historical service/subject bindings, a private launch snapshot and positive revision; `public.reflection_task_section` owns task-section lifecycle, child Thread binding and CAS; reports gain a nullable unique task link; events require positive unique task sequence. `dream.reflection_task_authorities` is separate from frozen `identity.runtime_delegations` and stores only hashed/encrypted task-section-thread authority with hard maximum expiry and revocation. No normal database has applied this candidate. Sync 2026-09-15.

Forward 0062 additively binds optional `identity.runtime_delegations` rows to an exact Story confirmation message and claim. Existing OAuth rows retain NULL source fields. Claim-bound grants keep the existing `idg_`/purpose DTO while Admin revalidates the current message claim and database-clock lease before every data UOW. Capability `identity.runtime-confirmation-claim.v1` is published only after columns, FK, unique source index and row-shape CHECK. Sync 2026-09-16.
