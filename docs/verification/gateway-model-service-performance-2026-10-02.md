## 指标与成功口径

以下 `T` 为单阶段从同时释放工作线程到最后在途请求读到 EOF 的真实墙钟秒数，包含阶段末尾排空；质量检查与预热不进入阶段 QPS/TPS。JSON 时长保留 6 位小数，作为派生速率的统一分母；表格时长展示 3 位小数，速率保留 4 位。报告保留实际时长、样本量和停止原因，不能把配置的 30 秒当成每阶段实际测满 30 秒。

| 指标 | 计算方法与含义 |
| --- | --- |
| 发起 QPS | 本阶段请求数 / T |
| HTTP 成功 QPS | HTTP 200 数 / T；流式响应可能在 200 后报错 |
| 协议成功 QPS | HTTP 200、无流式错误、收到结束原因与 `[DONE]` 的请求数 / T |
| 有效 QPS | 协议成功、usage 完整、`finish_reason=stop`、正文严格匹配 1–20 数列的请求数 / T |
| 输入 TPS | 协议成功请求报送 `prompt_tokens` 总和 / T |
| 输出 TPS | 协议成功请求报送 `completion_tokens` 总和 / T |
| 总 TPS | 协议成功请求报送 `total_tokens` 总和 / T；不能等同于输出 TPS |
| TTFT | 从客户端发出请求前开始计时，到解析到首个非空 `delta.content`；不算响应头、角色/空事件或推理事件 |
| E2E 延迟 | 从客户端发出请求前到流关闭 EOF；包含实际结算与流收尾等待 |
| 传输/协议错误率 | 未达到协议成功的请求数 / 本阶段请求数 |
| 业务质量失败率 | 未达到有效回复要求的请求数 / 本阶段请求数 |
| 空回复率 | HTTP 200 且正文去空白后为空的次数 / HTTP 200 次数 |

TTFT 是客户端看到首个正文片段的时间；一个 SSE 片段可能携带多个 Token，接口没有提供每个 Token 的独立到达时间。输出 TPS 采用报送的 usage，部分模型可能包含推理等不可见生成 Token，不能解释成用户可见文字的 TPS。本轮不伪造 Token 级 ITL 或 TPOT。

P50/P95/P99 使用最近秩法：排序后取第 `ceil(n*p)` 个样本。TTFT 仅纳入协议成功且实际有正文的请求，E2E 仅纳入协议成功请求；失败请求的状态、延迟和错误码保留在 JSON。无正文的 TTFT 标 `—`，不按 0 毫秒填充。小样本的 P99 常等于最慢一次，不能解释为可靠的长期尾延迟。

实现依据：[首正文事件计时](/Users/dmeck/project/ink-admin-memory/scripts/benchmark-gateway-stream.py:80)、[质量与完整流判定](/Users/dmeck/project/ink-admin-memory/scripts/benchmark-gateway-stream.py:91)、[指标分母](/Users/dmeck/project/ink-admin-memory/scripts/benchmark-gateway-stream.py:118)。
