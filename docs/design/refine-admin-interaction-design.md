# Refine 管理后台交互设计（PostgreSQL 完整版）

## 目标

把 Ink Memory Admin 建成可执行运营动作的控制台，而不是只读报表。根路径进入 `/admin`，登录后按权限展示 Story、用户、模型、计费、网关、权限、系统和审计模块。

## 全局交互

- 桌面端固定侧栏，窄屏使用横向可滚动导航。
- 所有列表提供服务端分页、排序和字段白名单过滤。
- 记录 ID 在需要后续更新/删除的列表中明确展示。
- 创建、更新和永久删除通过 CRUD Workbench 执行；删除必须二次确认。
- 财务、Provider、平台用户和管理员不允许硬删除，改用停用/撤销/冲正。
- 成功后刷新对应 Refine list/detail cache；失败展示服务端安全错误文案。

## Story 数据运营

页面按依赖顺序组织：工作区 → 项目 → 角色 → 场景 → 工作流。

每段包含：

1. 资源说明和 JSON 字段模板；
2. 创建、按 ID 更新、按 ID 删除；
3. 当前记录列表和关键状态；
4. 外键冲突、唯一键冲突、校验失败的明确反馈。

## 模型和计费

- Provider：状态、Endpoint、超时、重试、凭据轮换；凭据永不回显。
- Model：稳定别名与上游型号解耦，配置能力和上下文窗口。
- Pricing：按模型、用户层级和生效时间窗定价，禁止活动规则重叠。
- Model Permission：按用户与模型覆盖启停、RPM、每日/月度 Token 限额；删除覆盖后恢复默认策略。
- Billing：余额、预授权、Token 明细、不可变账本；充值要求原因和幂等键。
- Gateway：请求状态、Provider 错误、延迟、计费及分钟/日/月限流窗口；未知用量进入人工结算面板。

## 权限和系统

- 管理员：创建、停用、改密、分配角色；不硬删除。
- 角色：自定义角色 CRUD；内置角色不可删除，super_admin 权限集由迁移维护。
- 权限代码：系统资源清单，只读。
- 系统设置：category/key 唯一；敏感值只允许覆盖，读取永远脱敏。

## 状态与可访问性

- loading、empty、error、forbidden 必须有明确状态。
- 表格保留横向滚动，不造成页面级横向溢出。
- 表单控件具备 label，按钮和导航可用键盘操作。
- 登录失败不泄露账号存在性或服务器细节。
