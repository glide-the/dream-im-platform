# 模块交互：Admin Shell 与运营总览

> 返回：[全局交互规范](../refine-admin-ui-v3-interaction-design.md) · PRD：[平台基础](../../prd/modules/00-platform-foundation.md)

> 实现状态：登录、Shell 与 Story 运营快照已实现；下述完整 Gateway/计费摘要、指标来源元数据和页面级 permission 403 是目标设计。当前数据 API 会 403，但直接页面请求可能先返回 200 壳层。

## 1. 页面目的

所有管理员通过统一 Shell 识别当前模块、权限和系统状态；运营总览帮助快速进入真实异常或待办，不执行跨域写操作。

## 2. Shell

- Desktop：248px 固定侧栏、顶部上下文栏、单一主滚动；导航按剧本、模型、订阅、计费、Gateway、用户、权限、资源、系统分组。
- Mobile：菜单按钮打开全高导航 Drawer；当前分组展开，点击路由后关闭；Escape/遮罩/关闭按钮归焦菜单。
- 当前项用 2px 左线、字重和小面积黄色标识；隐藏无权项。当前直接访问具体页面可能先获得 200 壳层，受保护数据 API 才返回 403；页面级服务端 403 是待实现目标。
- 面包屑以真实路由层级生成；详情关闭后返回原筛选/分页/滚动位置。

## 3. 登录与初始化

| 字段 | 控件 | 校验/恢复 |
|---|---|---|
| 显示名称 | text | 1–120；首错聚焦 |
| 管理员邮箱 | email | 合法邮箱、trim/lowercase |
| 密码 | password + 本次显隐 | 最少 14；不进入日志 |
| 首次启动密钥 | secret | 只提交；失败统一 403，不提示哪部分错误 |

已初始化时只显示登录。登录成功安全返回原 URL；401 清除保护内容。按钮提交中禁止重复，错误保留邮箱但清空密码/密钥。

## 4. 总览布局

目标顺序：数据源状态 → 今日 Gateway/Token/费用 → 结算失败/Provider 异常 → Story 待办 → 最近审计。每项显示数值、时间窗、时区、更新时间、来源与跳转。当前 UI 只渲染真实用户、Workspace、Story、待审核 Story 及最近 Story/操作；虽 API 已返回模型、请求、Token、费用和结算失败，尚未展示，不能作为已验收能力。

Loading 保留网格；部分依赖 503 时仅对应块不可用。没有异常显示“当前无待处理项”，不显示庆祝性虚构指标。

## 5. 响应式与无障碍

- Desktop 2–4 列事实摘要，列表占整行；Mobile 单列并把主要异常置顶。
- 页面 H1 聚焦目标；skip link 跳到主内容；数据刷新用 polite live region。
- 统计图必须有文本摘要/表格替代；状态不用颜色单独表达。

## 6. 交互验收

- UI-FND-01：键盘完成登录、导航、折叠、跳转和退出。
- UI-FND-02：401/403/503 不残留上一用户或上一请求数据。
- UI-FND-03：两视口无根横滚；移动 Drawer 锁焦并正确归焦。
- UI-FND-04（目标）：总览每个数字均能定位到来源模块或明确不可用原因；补齐 Gateway/计费摘要前不通过。
