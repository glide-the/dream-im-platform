# deploy/autodl-ssh

## 定位

该目录是 Admin 在 AutoDL/SeetaCloud SSH 主机上的直接发布平台，与 `deploy/remote-ssh` 的 Docker、nginx、ECS 共享网络路径完全分离。

## 合同

- 代码、版本化 release 和配置位于 `AUTODL_APP_ROOT`；PostgreSQL 固定位于 Admin 服务用户拥有的 `/root/ink-autodl/data/postgres`，共享 Artifact 位于 Dream `AUTODL_DATA_ROOT/artifacts`。
- Admin 仅监听 `127.0.0.1:6008`，公网地址由 SeetaCloud 端口映射提供；脚本不安装或配置 nginx。
- `@ink-memory/db` 继续唯一管理嵌入式 PostgreSQL 和 Drizzle migration；应用启动不执行 DDL。
- PostgreSQL 及 Admin 以专用非 root 用户运行，`screen` 只负责断开 SSH 后的进程存活。
- Next.js 构建默认限制为 `AUTODL_BUILD_CPUS=1` 和 1024 MiB V8 old-space；DB runtime 优先硬链接复用 lock 与 package contract 完全相同的上一版不可变依赖树，依赖变化时的 fallback 打包使用独立的 `AUTODL_PACKAGE_MAX_OLD_SPACE_MB=384`；两项预算都可通过显式平台配置调整。
- `init-admin-data.sh` 幂等校正 owner/group/mode、拒绝符号链接，并在旧 Dream-root 或 `/var/lib/ink-memory` cluster 存在时 fail closed；它不会移动、删除或恢复真实数据。
- `prepare-env.sh` 从已有安全配置投影 `.env`，不会打印 secret；生成文件被 gitignore。
- `bootstrap` 只允许向零用户表目标导入本机嵌入式 PostgreSQL 的逻辑备份；常规发布使用 `deploy`。
- restore 后必须通过真实 `users` 行与业务表断言才允许 migration；失败重试可用 `AUTODL_BOOTSTRAP_DUMP` 复用远端备份。
- `rollback` 只切换应用 release，不逆转 migration 或数据库数据。

## 入口

- `prepare-env.sh`：生成 AutoDL runtime env，并写入本地 gitignored `.env`。
- `platform.env`：从 `platform.env.example` 复制的、gitignored 的 SSH 与公网映射配置；示例固定记录当前生产公开域名，`deploy.sh` 自动读取并投影为 Admin 登录 Origin allowlist。
- `deploy.sh`：`check|plan|sync|build|bootstrap|deploy|migrate|start|stop|status|logs|verify|rollback`。
- `runtime/start-admin.sh`：screen 内的前台监督入口，不接受或记录明文 secret 参数。
- `runtime/init-admin-data.sh`：部署和独立栈启动共用的 Admin home/data 初始化器。
- `test-topology.sh`：provider-free 校验 env 投影、owner/mode、幂等性与旧数据/symlink 边界。
