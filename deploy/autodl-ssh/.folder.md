# deploy/autodl-ssh

## 定位

该目录是 Admin 在 AutoDL/SeetaCloud SSH 主机上的直接发布平台，与 `deploy/remote-ssh` 的 Docker、nginx、ECS 共享网络路径完全分离。

## 合同

- 代码、版本化 release 和配置位于 `AUTODL_APP_ROOT`（默认 `/root/ink-autodl/admin`）；PostgreSQL 与 artifact 数据位于 `AUTODL_DATA_ROOT`。
- Admin 仅监听 `127.0.0.1:6008`，公网地址由 SeetaCloud 端口映射提供；脚本不安装或配置 nginx。
- `@ink-memory/db` 继续唯一管理嵌入式 PostgreSQL 和 Drizzle migration；应用启动不执行 DDL。
- PostgreSQL 及 Admin 以专用非 root 用户运行，`screen` 只负责断开 SSH 后的进程存活。
- `prepare-env.sh` 从已有安全配置投影 `.env`，不会打印 secret；生成文件被 gitignore。
- `bootstrap` 只允许向零用户表目标导入本机嵌入式 PostgreSQL 的逻辑备份；常规发布使用 `deploy`。
- restore 后必须通过真实 `users` 行与业务表断言才允许 migration；失败重试可用 `AUTODL_BOOTSTRAP_DUMP` 复用远端备份。
- `rollback` 只切换应用 release，不逆转 migration 或数据库数据。

## 入口

- `prepare-env.sh`：生成 AutoDL runtime env，并写入本地 gitignored `.env`。
- `platform.env`：从 `platform.env.example` 复制的、gitignored 的 SSH 与公网映射配置；`deploy.sh` 自动读取。
- `deploy.sh`：`check|plan|sync|build|bootstrap|deploy|migrate|start|stop|status|logs|verify|rollback`。
- `runtime/start-admin.sh`：screen 内的前台监督入口，不接受或记录明文 secret 参数。
