# Expert Prompt Architect 记录（非递归）

## Optimized Prompt

基于 Stage 1 PRD 与原始品牌封面，仅提取“暖纸、深棕、少面板、轻分隔、单一虚线边界”的视觉原则，
为 Ink Memory Admin v3 的专项“紧凑页面/列表表头 + 可折叠筛选”输出中文 ASCII 结构草图。
范围只含页面标题、列表标题、查询栏、展开筛选、状态摘要、数据表与分页；必须覆盖 Desktop 收起、
Desktop 展开、已应用筛选且存在未应用草稿、Mobile Filter Sheet、无筛选五种状态。每个结构块使用
稳定 ID，并标明共享组件边界、独立业务适配槽、URL 真相源与状态不丢失规则。实现基线为仓库现有
Next.js / Refine / Tailwind CSS 4、本地字体、本地 SVG 或 React SVG；不得引入模板 CDN、Google Fonts、
Font Awesome、卡片墙、假数据或完整平台信息架构。

## Optional Enhancers

- 用 1440×1000 和 390×844 验证首屏密度、44×44 命中区及根页面无横向溢出。
- 用关系 Combobox、长标题、3 个筛选条件和 100+ 条结果做密度压力测试。
- 用 Playwright 覆盖收起/展开、应用/清除、刷新、深链、前进后退、Sheet 归焦与错误保留。
- 用 axe 检查 `aria-expanded`、具名 region、表格 caption、错误关联与键盘顺序。

# Ink Memory Admin v3：专项页面结构草图

> Stage 2 — Structure Sketch Designer
> 视口：Desktop `1440×1000`；Mobile `390×844`
> 原图是品牌封面，不是后台截图；其大面积留白不直接转译为控制台纵向空间。

## 1. 稳定结构骨架

```text
[A0 页面内容区]
├─ [A1 PageHeader：页面级 H1 / 短说明 / 元信息 / 唯一主动作]
└─ [B0 ListSurface：唯一虚线 Paper Boundary]
   ├─ [B1 AdminListHeader：资源 H2 或 sr-only / 结果数 / 刷新]
   ├─ [C0 AdminQueryBar]
   │  ├─ [C1 PrimaryQuery：关键词或精确 ID]
   │  ├─ [C2 FilterToggle：筛选 / 数量 / aria-expanded]
   │  ├─ [C3 AppliedFilterSummary：已应用摘要 / 可逐项移除]
   │  ├─ [C4 DraftHint：有未应用更改]
   │  └─ [D0 SecondaryFilters：Desktop region / Mobile Sheet]
   ├─ [E0 QueryStatus：范围 / 总数 / 来源 / 同步或错误]
   ├─ [F0 DataRegion：唯一局部横滚表格壳]
   └─ [G0 Pagination：分页 / pageSize / 范围]
```

稳定性约定：`A–G` ID 在所有资源与视口中保持语义不变；隐藏模块仍保留同一语义归属，
不得因业务模块不同重新编号。`D0` 只改变承载方式，不改变筛选字段定义或草稿语义。

## 3. Desktop 展开态

```text
┌──────────────────────────────────── [C0 AdminQueryBar] ───────────────────────────────┐
│ [C1 关键词____________________________] [C2 收起筛选 0 ▴]                            │
│──────────────────────────────────────────────────────────────────────────────────────│
│ [D0 SecondaryFilters / role=region / aria-label="资源筛选"]                         │
│ [D1 主要关系 Combobox________] [D2 状态/枚举________] [D3 日期从____至____]          │
│ 可见 label + 帮助/错误关联；焦点进入第一个次要筛选                                  │
│                                                         [D4 清除] [D5 应用（禁用）] │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

- `D0` 与 `C0` 以一条 solid border 分隔，不新建卡片或 shadow。
- `D5` 仅在草稿与 URL 已应用值不同时启用；Enter 应用，应用后 `page=1`。
- 点击 `C2` 关闭后焦点归还触发器；收起不请求、不清草稿、不清已应用值。
- 关系筛选保存稳定 ID；显示 label 由 hydration 获得，不把 label 写进 URL。

## 4. 已应用筛选 + 收起后待应用草稿

```text
┌──────────────────────────────────── [C0 collapsed + active + draft] ─────────────────┐
│ [C1 搜索：alice@example.com_________] [C2 筛选 3 ▾]                                  │
│ [C3 已应用 3 项] [状态：active ×] [套餐：pro-v3 ×] [+1]  [C4 ● 有未应用更改]       │
│ [D0 隐藏，但保留打开前草稿；结果仍按 URL 中 3 项已应用条件查询]                      │
├──────────────────────────────────────────────────────────────────────────────────────┤
│ [E0] 第 1–20 条 / 共 {真实总数} · 正在同步时保留旧结果，不显示伪 0 条               │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

`C3` 最多显示 2 个 chip，其余聚合为 `+N`；逐项移除同时更新 URL 并回到 `page=1`。
`C4` 不靠颜色单独表达，折叠后仍可见。外部 URL、刷新、深链和前进/后退到达时，
以 URL 白名单值重建 applied，并同步 draft，避免旧草稿覆盖分享链接。

## 5. 无筛选与空结果状态

```text
┌──────────────────────────────────── [C0 no-filter] ──────────────────────────────────┐
│ [C1 搜索____________________________] [C2 筛选 0 ▾]                                  │
│ [C3 不渲染 chip] [C4 不渲染提示]                                                     │
├──────────────────────────────────── [E0 / F0] ────────────────────────────────────────┤
│ 正常无筛选：显示全部允许数据的范围、总数与表格。                                    │
│ Filter Empty："没有符合当前条件的结果" + 条件摘要 + [清除筛选]。                   │
│ System Empty："尚无可显示的数据" + 真实原因/权限内主动作；不显示清筛。              │
│ Query Error：保留 URL、草稿、展开态和旧结果上下文 + request ID + [重试]。            │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

系统默认筛选可继续生效，但不计入 `C2` 数量；失败不可伪装成空结果或 `0` 条。

## 7. 共享组件边界

```text
[AdminListHeader B1]
[AdminQueryBar C0]
├─ [PrimaryQuery C1]
├─ [FilterToggle C2]
├─ [AppliedFilterSummary C3]
├─ [DraftHint C4]
└─ [SecondaryFilters D0] ── viewport ──> [DesktopFilterRegion] / [MobileFilterSheet]
[useAdminListQueryState H0]
├─ parse/validate/serialize URL whitelist
├─ applied(URL) ↔ draft(local)；filter change → page=1
└─ back/forward、竞态取消、摘要 formatter、稳定 ID hydration
```

`AdminResourceTable` 与 `AdminResourceManager` 共用以上边界及 `H0`，不各自复制 URL/draft 语义。
Tailwind CSS 4 只使用仓库现有 token/class；图标为本地 SVG/React SVG 且 `currentColor`；字体为本地资源。

## 8. 独立业务模块适配索引

| ID | 适配槽 | 各模块独立保留内容 | 默认常显 / 收起 |
|---|---|---|---|
| I1 | Story | workspace/story 关系、审核/发布状态、版本动作 | 关键词常显；关系/状态收起 |
| I2 | 用户/订阅 | email/精确 ID；套餐版本、周期、取消/恢复 | 搜索常显；详情不重复 B1 |
| I3 | 套餐/权益 | 发布/关闭/复制新版本；额度、Token、micro-USD 来源 | 状态与关系收起 |
| I4 | Gateway Key | key prefix；一次性回执、撤销/轮换说明 | prefix 常显；状态收起 |
| I5 | 请求/用量 | request ID、模型、时间、状态、Token、延迟、错误 | request ID/时间常显 |
| I6 | 只追加账本 | 用户关系、时间、事件、金额快照；无编辑/删除 | 已应用摘要常显 |
| I7 | Provider/Model/Pricing | 能力、价格版本、全屏编辑；Secret 不回显 | 列表紧凑；复杂编辑独立页 |
| I8 | Role/Storage | permission、record state；健康/容量只读事实 | 搜索常显或默认收起 |

适配模块只提供字段定义、URL key 白名单、summary formatter、`primary/secondary` 优先级及领域动作；
不得改写 `A1–H0` 的交互语义。高风险动作不进入 Header 主位，表格列、权限、服务端查询和详情流程
不属于本专项；Route Handler 继续只编排，Zod、SQL、事务和权限仍在 `app/lib/**`。
