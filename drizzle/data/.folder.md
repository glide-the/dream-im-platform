# Explicit data migration contract

- 本目录只承载显式、可审计、默认 dry-run 的 PostgreSQL 数据 runner；schema/DDL 仍只由 `drizzle/**` 前向 migration 管理。
- runner 必须验证目标数据库身份、依赖 migration/capability、使用事务与 advisory lock，并输出不含 DSN、Secret、用户标识或业务正文的回执。
- `gateway-default-token-limits.mjs` 只统一 `platform_users` 的 429 日/月安全阈值；它不发放订阅 Token、不改 Allowance、不充值现金余额。
- `chat-history-final-projection.mjs` 默认仅 dry-run；只有显式 `--apply` 才按纯合同模块严格回填 assistant final 投影。无法唯一判定 final 的旧行保持未投影并由 Dream 兼容读取完整 `parts`。
- `provider-managed-accounts.ts` 是 journal 路径稳定的默认 dry-run 薄入口，全部行为复用 `provider-managed-accounts-core.ts`；发布编排先用无数据库 `--preflight` 校验 credential key 与 identity pepper，再由核心在单一 serializable 事务和 advisory lock 内把旧 Provider AAD credential 重加密到 account ID AAD、用独立 pepper 生成 identity HMAC、保持旧 Provider 的 pinned 行为、取消并擦除 active attempt。存在 `pending/processing/failed` revocation job 时直接阻断，且日志/收据仅含聚合计数。
- 源码薄入口只从 `MIGRATION_DATABASE_URL` 读取目标；发布编排使用 `@ink-memory/db` 的 compiled CLI，通过与 schema migration 相同的 connection resolver 注入目标。
- `provider-owned-credentials.ts` 在五表锁与 serializable transaction 内按 pinned/default 的当前 effective binding 计算唯一 owner；deleted Provider 只规范化为 pinned/null tombstone，不参与 owner 竞争。其余共享或孤儿 live credential、active attempt、非终态 revoke、悬空/adapter mismatch 一律在写入前阻断。成功路径只回写 `provider_id`、direct pointer、internal pinned mode 并清空 defaults，不复制、删除、重加密 credential。
- `provider-deleted-credential-orphans.ts` 在 0051 后识别 live credential 的 owner 缺失、已 tombstone 或未 direct-point 回该 credential；默认 dry-run，apply 只将 orphan 本地断开、递增 epoch/revision、清除 envelope/lease/scope/expiry 并取消相关 active attempt。它保留 credential/attempt 历史，不创建 revocation job，回执固定声明 `remoteRevocation=not_attempted`，不得把本地清理伪报为远端撤销成功。
- 真实 `ink-memory` 执行需用户明确授权；破坏性或重复验证必须使用具名可删除的隔离 PostgreSQL。
