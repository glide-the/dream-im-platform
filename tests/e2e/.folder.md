# tests/e2e — Folder Contract

- 本目录通过公开生产入口验证 Admin/Gateway/Dream 交互；不得复制测试专用 Route Handler、状态机、Gateway 或 Provider 成功分支。
- 任何数据库写入只允许明确命名、可删除的隔离 PostgreSQL，必须显式提供 `TEST_DATABASE_URL` 并由 `INK_USE_TEST_DATABASE_URL=1` 选择；不得迁移、清理或写入共享 `localhost:5433/ink-memory`。
- Provider/网络调用使用受控本地 mock HTTP server；mock 只实现上游协议，不拦截 Admin API 伪造成功，也不执行真实模型或消费者账号登录。
- `provider-credential-lifecycle.spec.ts` 覆盖静态 credential 的 disabled/unverified 创建、验证启用、成功/失败轮换、revision 409、旧 effective 保留和 Secret 非回显。
- `provider-delete-dependencies.spec.ts` 通过 Provider 卡片的一次确认交互覆盖：有关联 Model/Pricing 时服务端 409 且中文提示先清依赖，三类记录保留；零依赖 Provider 删除成功并从刷新列表消失、详情返回 404。
- `provider-managed-auth.spec.ts` 通过公开 Admin route/UI 覆盖空 registration env 下内置 Codex 产品配置 ready、添加账号按钮 enabled、点击前零 attempt 与 Secret 非回显。
- `provider-managed-auth-configured.spec.ts` 由 `run-provider-managed-auth-e2e.mjs` 创建具名隔离 PostgreSQL、官方 host TLS fake 和严格 CONNECT proxy；不注入 Copilot client/scope/fingerprint，通过系统 Chrome 实际点击两个 Provider 各自连接一个账号。fake 同时实现 Codex、xAI、Copilot 三种产品 model endpoint 形状；浏览器主链路用 Copilot 验证首个账号自动 catalog 失败仍 connected、无 Model/Pricing、UI 手动重试获得 snapshot，并发重复 Discover 在 advisory lock 下复用同一 snapshot，review 中 unsupported Responses 模型不可选，Apply 后新 Model 为 disabled 且仍无 Pricing；第二个账号验证 post-connect 自动 snapshot/review。既有第二次无 target start 409、Provider 各自 Gateway 解析、deleted-owner orphan 原子退役/恢复、live owner 重复拒绝与 Secret 非回显/不落明文继续保留。
- managed Device 的 pending/slow_down/拒绝/超时、refresh singleflight/rotation 与 remote revoke 其余协议态继续由 focused integration tests 覆盖；不得用浏览器 route 伪造服务端成功或冒充真实业务验收。
- 经 Admin API 创建 active Provider 的 fixture 必须遵循 disabled → Model → PATCH active + expected auth revision；直接 SQL active/unverified 只用于明确模拟 migration 兼容状态，不能伪标 valid。
- 浏览器运行优先复用本机 Chrome，只做一次启动 preflight；诊断必须捕获 console、page error、request failure 与意外 5xx。
